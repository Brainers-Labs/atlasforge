## [0.1.0a2] - 2026-10-08

### Added
- `atlasforge.eval.metrics.mean`, an exactly rounded arithmetic mean, so that an average written into a report does not depend on the Python version that computed it. The reason is the fix below.

### Changed
- **The project is on PyPI**, as `brainers-atlasforge` at version `0.1.0a2`. It is a pre-release, so `pip install --pre brainers-atlasforge` is what finds it; without `--pre`, pip will not see it at all. The import name and the command both remain `atlasforge`, which is the same split as Pillow and PIL. Uploading is deliberately not part of `release.yml`: a tag push can never put anything on the index, and `publish.yml` is run by hand.
- **The version is `0.1.0a2`, and the first upload could not be `0.1.0a1`.** That tag is six commits behind `main` and predates three bug fixes — both py3.10 CI failures and the Windows one — and its `pyproject.toml` still pointed `Homepage` and `Issues` at the personal account. PyPI never lets a version's metadata be edited, so uploading it as it stood would have written the old URLs into the permanent record. `v0.1.0a1` keeps its tag, its release and its checksums, which is the honest record of what was built from it.
- The repository moved from `im-aderm/atlasforge` to the **`Brainers-Labs`** organization, which is the name the packaging metadata has carried as the author since the first commit. Every URL that names the project moved with it: `Homepage` and `Issues` in the metadata, the documentation site's `site_url`, `repo_url` and `repo_name`, the clone commands in the README, the installation guide and the handoff notes, the security-advisory and issue-template links, the Colab badge, and the notebook's install line — the last of these together with the test that reads it, since a notebook and its assertion drifting apart is exactly what that test exists to catch. GitHub redirects the old addresses, so no existing clone, fork or bookmark breaks.
- The README, this changelog and `OVERVIEW.md` now name the published version instead of describing it as *unreleased*, and the README's Install section leads with the two-line `pip install` rather than telling a reader it is not on PyPI yet. The README's own links are absolute GitHub URLs, because PyPI renders that file as the project description and a relative `docs/index.md` is not a link to anything there. The notebook installs the published distribution rather than a `git+https` clone for the same reason.

### Fixed
- The committed example reports were not reproducible on Python 3.10. `tests/unit/test_examples.py` compares them byte for byte, and on all three 3.10 runners it failed on a single last digit — the generator produced `77.40682504276319` where the committed file says `77.40682504276317`. The cause is not the report code but `sum`: CPython 3.12 gave it Neumaier compensated summation for floats (gh-100425), so a mean written as `sum(values) / len(values)` describes the interpreter that ran it. 3.12 and later agree with the committed reports; 3.10 and 3.11 accumulate left to right and land one unit in the last place away. Every reported average — the per-metric and latency means in a report, the base, candidate and slice means in a comparison, and macro-F1 across classes — now goes through `atlasforge.eval.metrics.mean`, which uses `math.fsum`. `fsum` is exactly rounded, so its result depends on neither the version nor the order of the values; that it is exactly rounded was checked against rational arithmetic over 60,000 random lists rather than assumed. No committed example changed: the numbers on disk were already the correctly rounded ones, and 3.10 was the outlier.
- The test `test_help_works_without_a_gpu_which_is_how_a_reader_learns_the_flags` failed on the Windows runner. It spawns `scripts/live_smoke.py --help` and declared `encoding="utf-8"` on the parent while the child writes with the platform default — cp1252 on Windows — so the em dash in the help text arrived as the byte `0x97`, `subprocess`'s reader thread died with `UnicodeDecodeError`, `stdout` came back as `None`, and the assertion raised `TypeError` instead of comparing a string. It was the only one of the six subprocess call sites in the suite to pin an encoding; the rest use `text=True` alone, which reads with the encoding the child actually wrote. On Linux both sides default to UTF-8, which is why only Windows caught it.
- `mypy` failed on both Python 3.10 runners in `asr/chunking.py`, and the cause was not Python 3.10. numpy dropped 3.10 in 2.3, so the 3.10 cells resolve numpy 2.2 while the 3.13 cells resolve 2.5, and 2.2's stubs do not match the outer `np.maximum` when its first argument is an unannotated nested call: mypy falls back to `Any`, `astype(np.float32)` then returns `Any`, and `warn_return_any` — part of `strict` — rejects the return. The frame-level dB intermediate is now named and annotated `npt.NDArray[np.float64]`, which resolves the overload identically on numpy 2.2 and 2.5 — the same remedy `pcm_to_float32` already needed. The earlier local check had called this clean, but only under `--follow-imports=skip`, which suppresses missing-module errors: that flag was hiding the answer rather than giving one.
- `config.py` and `tests/unit/test_packaging.py` imported `tomllib` as `try`/`except ModuleNotFoundError`. That is correct at runtime, but mypy resolves imports statically, so on a 3.10 target — whose typeshed has no `tomllib` — every 3.10 runner failed with `import-not-found` as soon as those files were committed. Both now use a `sys.version_info >= (3, 11)` guard, which is what mypy narrows on. Runtime behaviour is unchanged; `tomli` was already a dependency for `python_version < '3.11'`.
- The release workflow published `v0.1.0a1` as an ordinary release, so an alpha appeared as *Latest* on the repository — a maturity claim the version deliberately does not make. `gh release create` marks a release full unless told otherwise, so the workflow now reads `packaging.version.Version(...).is_prerelease` and passes `--prerelease` for a PEP 440 pre-release (`a1`, `b2`, `rc1`, `.dev1`). The release already published was marked by hand, so this fix is what keeps the next tag from needing that.

## [0.1.0a1] - 2026-10-08

### Added
- Project skeleton: src layout, ruff, mypy (strict), pytest, CI matrix, pre-commit with gitleaks.
- `atlasforge doctor` (and `--json`).
- Error hierarchy with actionable hints, shared types, `mask_secret`.
- `Backend` protocol.
- Tone-aware and tone-insensitive text normalisation for ha/yo/ig/en.
- Strict JSONL dataset loader (line-numbered errors, content fingerprint, unique ids).
- Metrics (exact match, accuracy, macro-F1, chrF/chrF++, WER, CER, latency percentiles) and `score_run`: every text metric under both tone-aware and tone-insensitive views; failed or missing predictions count as wrong; per-example values kept for paired statistics.
- `compare`: paired bootstrap, exact McNemar, slice analysis (n>=30 rule), Markdown/JSON reports.
- OpenAI-compatible backend (retries, error mapping, no response bodies in messages, HTTPS-or-loopback guard).
- `local` transformers backend (stand-in tested only; not yet run against real weights).
- ASR: ffmpeg decoding to 16 kHz mono, windowing past the 30 s limit, seam-aware transcript merging, `LongAudioBackend`.
- `dataset validate`: duplicates, conflicting labels, leakage, Unicode health, diacritic statistics, class balance.
- CLI: `run`, `transcribe`, `eval`, `report`, `compare`, `dataset validate`; `python -m atlasforge`.
- `finetune`: QLoRA recipe (config, data checks, `--dry-run`, leakage/truncation guards, TRL argument-name detection) and `training_run.json`; not yet run on a GPU.
- `card`: licence-aware model cards from `comparison.json` and `training_run.json`.
- `--adapter` on the local backend (and `run`/`eval`) to evaluate LoRA adapters; the adapter is part of the model identity.
- Circuit breaker: `eval` aborts after N consecutive failures (default 20) and stays resumable; bounded in-flight window for threaded runs.
- Resumable evaluation runner: manifest guard against mixing runs, per-example error isolation, crash-safe results file, optional threaded concurrency.
- `atlasforge demo`: synthetic data and two finished runs, so the quickstart reaches a comparison with no model and no network.
- Documentation site (MkDocs Material): guided path, concepts, task guides, generated CLI/API/metrics/flags reference, troubleshooting, FAQ and an honest status page. A test checks every documented command and flag against the live CLI, a test runs every runnable snippet against demo data, and the site builds strictly in CI.
- `atlasforge.evaluate()`, `compare_runs()` and `score_finished_run()`: the high-level Python API, with `__all__` declaring the stable surface.
- Custom metrics: your own `(prediction, reference, example) -> float` callable, in Python or as `--metric module:function`; per-example values flow into `compare`.
- Failure-mode flags: empty, repeated and truncated output, format compliance, missing required terms, number mismatch, and a script check. Deterministic rules over the text — not a quality score and not a hallucination rate — summarised per run and compared run-by-run.
- ASR error analysis: the most substituted word pairs, the words dropped and invented, tone-only substitutions marked as such, and pooled WER by reference length.
- HTML reports: `report.html` and `comparison.html`, written by `eval`, `report` and `compare` beside the JSON and the Markdown. Each is one self-contained file — inline SVG charts, a dark-mode variant, no JavaScript, no external stylesheet, font, image or link — so it opens from the filesystem, air-gapped, or as an email attachment. Both renderers read the same report object as the Markdown, so the numbers cannot drift apart.
- `doctor` checks gated access: each NCAIR1 repository is probed and the exact accept-the-licence link is printed. A timeout is reported as unknown rather than as denied.
- Packaging is exercised in CI: the sdist and wheel are built, each installed into a fresh venv and run, and a core install is asserted to pull in no ML framework.
- Optional `atlasforge.toml` project settings: the nearest file at or above the working directory supplies defaults for `backend`, `base_url`, `model`, `quantize`, `device`, `timeout` and `retries`. Precedence is flag → environment variable → file → default; an unknown key is an error, and `doctor` reports which file is in effect.
- Release process: a tag-triggered workflow checks that the tag, the package version and the changelog agree, builds the sdist and wheel, installs the wheel into a fresh venv and runs it, and attaches everything with checksums to a GitHub release. Publishing to PyPI is separate and manual, using trusted publishing, so no tag push can upload on its own. The release steps are on the "Releasing" page of the documentation site.
- Live evidence: `scripts/live_smoke.py` runs eight checks against the real models — gated access on all five NCAIR1 repositories, whether the LLM loads and how much VRAM it uses, one generation per language with the tokenizer's chat template, the true `max_position_embeddings`, a served completion, one transcription per ASR model, whether speech models return timestamps, and the commit SHA of every repository — and writes a Markdown log to `evidence/live_<date>.md`. A check that cannot run is recorded as `not run` with the reason, never as a plausible figure, and a failure is a row rather than a crash. It has not been run yet: this is the instrument, and the log it fills in is still empty.
- Example output in `examples/reports/`: a report and a comparison in all three formats, generated from the synthetic demo data so that they can be read without a model. A test regenerates them from the current code and fails if a byte differs, so committed example output cannot drift away from what the tool now produces.
- A quickstart notebook (`notebooks/atlasforge-quickstart.ipynb`) that runs the whole workflow — score, compare, read the HTML — on the demo data, needing no model, token or GPU. Its cells are executed by the test suite in order, apart from the two marked `# notebook: colab-only` (the install and the real-model example), so a stale cell fails the build instead of a reader.
- "How AtlasForge integrates N-ATLAS": a concepts page listing the five official repositories, how a model is chosen and loaded by each backend, how the declared language selects a speech checkpoint, and where the boundary sits between a transport choice (any OpenAI-compatible server) and the models AtlasForge itself names. It is the page that answers the submission's "only official models" requirement.
- `atlasforge bench afrobench`: a documented wrapper around EleutherAI's `lm-evaluation-harness` for the published AfroBench-LITE suite. It builds the harness command for an official `NCAIR1` model, reads the harness's own results file and writes `bench.json` and `bench.md` beside it. The task identifiers come from the installed harness rather than from a list in the source, and a family the harness has no task for is reported as a gap rather than a zero — an absent number and a score of zero are not the same claim. The study's published figures are deliberately not included. Installed with the `bench` extra; its wiring is tested against stand-ins and it has not been run against the harness or the weights.
- The benchmark report records the two things that decide what its figures mean: `raw_path` names the file the harness actually wrote (it can ignore the path it was given), and `few_shot` records the `--num_fewshot` AtlasForge asked for, or `null` when it asked for none — in which case each task ran with the harness's own default, which is not necessarily zero-shot. It also renders chrF and BLEU at the harness's own scale instead of multiplying them by 100.
- Silence-aware audio chunking, opt-in with `--silence-aware` (or `silence_aware=True` on `atlasforge.evaluate()`): each window boundary moves up to two seconds to the middle of the quietest nearby 20 ms frame, if that frame is at or below the silence threshold, so a cut lands in a pause instead of inside a word. The number of windows and their overlap are unchanged, and a boundary with no pause in reach stays where the fixed grid put it. The fixed grid remains the default.
- Strict classification metrics, `accuracy_strict` and `macro_f1_strict`: the whole answer must *be* a label, so an answer that merely mentions one — `"not positive"` — no longer counts as a match. They are separate report keys rather than a mode, so a strict result can never be averaged with a loose one; the difference between the two measures how often a model answers more than it was asked.

### Changed
- **The distribution name is `brainers-atlasforge`, not `atlasforge`.** PyPI's `atlasforge` is an unrelated bioinformatics project, so `pip install atlasforge` would have installed someone else's package. The import name, the `atlasforge` command and every example are unchanged — the same split as Pillow and PIL. The extras that referred to the project by name (`atlasforge[local]`, `atlasforge[docs]`) were updated with it.
- Version is `0.1.0a1`.

### Fixed
- Install hints in error messages still named the old distribution. The rename updated the packaging metadata and the documentation, but not the five hints in `src/` — so a missing extra told you to run `pip install "atlasforge[local]"`, which is not a typo: it reaches the unrelated project that owns that name, and then fails on an extra it does not have. A test now reads the name from `pyproject.toml` and fails if any install command in the source or the docs names a different one.
- Three places named the LLM's repository with a `-8B` suffix, which is not what it is called on Hugging Face — the config module's own example, the configuration reference page, and a test fixture. Anyone copying the documented `atlasforge.toml` would have got a 404 from Hugging Face instead of a model. The name is now `NCAIR1/N-ATLaS` everywhere, and `tests/unit/test_model_ids.py` reads every `NCAIR1/...` identifier out of the source, the docs and the tests and fails if one is not among the five official repositories.
- The README never said how to install the tool. It is the front page of the public repository, and it went from the status banner straight to commands that assume `atlasforge` is already on `PATH`; the only install lines on it were for the `docs` and `dev` extras, which a user does not want. It now has an Install section — clone, virtual environment, `pip install -e .`, `atlasforge --version` — before the command list, with a pointer to the extras.
- The installation guide told Windows readers to run `.venv\Scripts\Activate.ps1` and stopped there. On a default Windows PowerShell that file is blocked — *"Activate.ps1 cannot be loaded because running scripts is disabled on this system"* — which is the first command those readers run, and the failure reads like a broken environment rather than a policy. The installation guide now gives the session-scoped `Set-ExecutionPolicy` fix plus an activation-free fallback that calls `.venv\Scripts\python.exe` directly, and the quickstart points at it.
