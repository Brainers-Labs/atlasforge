# NAIC Submission Checklist

Target: submit **Sun 11 Oct**. Hard deadline Mon 12 Oct, 11:59 PM WAT.

## 1. Working artefact
- [ ] Public GitHub repo, tag `v0.1.0`
- [ ] `pip install brainers-atlasforge` works from PyPI in a fresh venv (Linux, macOS, Windows). **Not `pip install atlasforge`** — that name is an unrelated bioinformatics project; the import name and the `atlasforge` command are unchanged.
- [ ] `doctor`, `run`, `transcribe`, `eval`, `compare` work against real N-ATLaS
- [x] Example reports committed under `examples/reports/` — `report.{md,json,html}` and `comparison.{md,json,html}`, all synthetic. `tests/unit/test_examples.py` regenerates them from the current code and fails if a byte differs, so they cannot describe an older version of the tool.
- [ ] Colab notebook(s) run top-to-bottom. Written (`notebooks/atlasforge-quickstart.ipynb`, offline demo path) and its portable cells are executed by `tests/unit/test_notebook.py`; **nobody has opened it in Colab and run it there yet**

## 2. N-ATLAS integration evidence
- [ ] `evidence/live_<date>.md` generated by `scripts/live_smoke.py`: repo IDs + commit SHAs of all 5 NCAIR1 models, hardware, sample I/O per language, timings. The script exists and is tested; **it has not been run**. `python scripts/live_smoke.py --out evidence [--quantize 4bit] [--audio-dir clips] [--base-url ...]` — every row it cannot fill says `not run` and has to be closed by hand before this box is ticked
- [x] Architecture diagram showing NCAIR1 models as the only models in the core path — `docs/concepts/n-atlas-integration.md`, whose diagram puts every model under an `NCAIR1` label, plus the repository table
- [x] Short "How AtlasForge integrates N-ATLAS" doc (backends, loading, routing) — the same page: the five repositories, how `openai` vs `local` load a model, how `lang` selects a speech checkpoint, and where the boundary is
- [x] Statement: no other foundation model used. CI tiny models are for wiring tests only. — "Where the boundary is" on that page, and `tests/unit/test_model_ids.py` fails if any identifier other than the five official ones is named anywhere in the project

- [ ] Round 1 → Round 2 improvement: issues found, issues fixed
- [ ] Measured metrics (time to first eval, success rate, usability score). No invented numbers.
- [ ] Any tester-produced reports (e.g. a Problem 03 team's compare report), with permission

## 4. Technical documentation
- [ ] Docs site live: quickstart (A/B paths), licences & access, guides (eval, compare, ASR, fine-tune, vLLM), CLI & API reference, dataset format, metrics & normalization, troubleshooting. **All the pages exist and build strictly in CI** (`mkdocs build --strict`, exit 0, plus a test that every page is in the nav and every documented command and flag is real). What is missing is the deploy: GitHub Pages has to be enabled in the repository settings, and that is a human step. The content, including `docs/concepts/n-atlas-integration.md`, is reviewable now.
- [ ] Hausa quickstart (reviewed by a named person). **Not started, deliberately**: writing it without a named native-speaker reviewer would put unreviewed Hausa in the docs, which is worse than not having the page.
- [x] README, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, CHANGELOG, LICENSE — all present, no placeholder email or org
- [ ] Benchmark pack PROVENANCE files with licences. **Blocked on a decision, not on work**: shipping a subset means inheriting its licence (FLORES-200 is CC-BY-SA-4.0, which is share-alike and a real question for an Apache-2.0 repository), so which packs to ship is the team's call. No pack is committed rather than committing one with a guessed licence.
